# 产品设计、题材规格与领域模型

## 1. 产品定位与边界

Nib 是面向个人自用的**本地桌面 AI 男频网文写作工作台**，核心形态是「**大纲与节拍驱动的半自动串行微批流水线**」。

### 我们解决的真实痛点
- **长篇吃书与状态漂移**：写到几十上百章后，模型忘记角色伤势、境界、所持法宝、资金数额与已埋伏笔。
- **网文节奏感缺失**：AI 默认写散文或流水账，缺乏男频必需的“立靶—蓄压—反转—爆发—留钩”节奏脉冲。
- **AI 腔与洗稿返工**：高频套话（“嘴角勾起一抹弧度”“眼神微眯”）、对称排比、章末鸡汤说教与长段文字墙。

### 明确不做（Out of Scope）
- 账号体系、多用户权限、云端同步与商业订阅计费。
- 面向纯手工敲字的富文本排版花哨特效，或“全自动无人值守连吐 100 章”黑盒工厂。
- 平台自动发布爬虫、AI 插图、有声听书、外部独立向量数据库服务（如 Milvus/Qdrant）。

## 2. 核心主循环：双人类闸门 + 串行微批

Nib 把每次创作切分为 **1~5 章的微批循环**，只在最需要作者把关的两个节点设闸门，中间繁重执行交由流水线串行跑完：

```text
[闸门 1：作者控骨架]                    [串行微批流水线（逐章 N -> N+1）]                     [闸门 2：作者高速审改]
卷纲目标/情绪曲线                       1. 编译「作战简报」(含前章 pending 状态)             1. 正文区扫视 AI 味/吃书标红
      │                                 2. 按节拍流式出稿 + 短段约束                        2. 病灶段局部 Diff 一键采纳
      ▼                                 3. 0成本本地 AI 味探测 + Critic 审校                3. 审查「记忆变更单」高危高亮
批量草拟 3~5 章纲/节拍 ─── 确认放行 ──► 4. 病灶段落手术润色建议               ──► 集中审阅 ──► 确认入库(committed) +
      ▲                                 5. 抽本章增量状态(pending)喂给下一章                       自动同步 Markdown 副本
      └─────── 改旧章触发下游脏标时返回微调 ◄───────────────────────────────────────────────────────────┘
```

### 为什么多章微批必须串行而非并行
第 `N` 章一旦出现主角重伤、得宝、破境或配角死亡，第 `N+1` 章编译上下文时必须立刻看到该变化。并行生成第 `N` 与 `N+1` 章必然造成因果撕裂。Nib 采用**串行接力**：第 `N` 章完成后抽出的增量写入 `pending` 态事件，第 `N+1` 章自动拼接 `committed + 同批 pending` 状态；若作者在闸门 2 修改并推翻第 `N` 章的关键剧情，第 `N+1..M` 章自动标记 `upstream_dirty` 提示重跑。

## 3. 男频多题材「题材包（Genre Pack）」规格

创建书籍时选定题材包（后续可在书籍设置中微调），底层数据库结构完全一致，仅预置不同的实体属性模板、爽点循环模板与防毒约束。

### 3.1 四套预设题材包

| 题材 ID | 名称 | 默认人物/实体快捷字段 | 默认爽点循环与节奏侧重 | 专属防毒与文风基线 |
| --- | --- | --- | --- | --- |
| `xuanhuan` | 玄幻 | `realm`(当前境界)、`physique`(体质/血脉)、`martial_arts`(功法武技)、`treasure`(兵器/异火/至宝)、`affiliation`(宗门/家族)、`injury`(伤势/底牌冷却) | 3~5 章一个小循环：立嘲讽靶 → 暗中积蓄/被轻视 → 关键场域展露底牌/越阶反杀 → 收获资源与旁观震惊 → 引出更高层级势力 | 严禁战力无故跨大阶碾压无代价；严禁反派全员降智送人头；战斗描写重招式博弈与结果落袋 |
| `xianxia` | 仙侠 | `cultivation`(修为境界)、`spirit_root`(灵根/道基)、`magic_method`(神通/秘术)、`natal_treasure`(本命法宝)、`lifespan`(寿元/因果线)、`status`(门派身份/洞府) | 4~6 章布局循环：得机缘线索/危机逼近 → 多方试探博弈 → 关键节点以小博大/破境劫数 → 利益兑现与抹除隐患 → 留更高因果悬念 | 禁用现代网络词汇与白话口水词出戏；区分“老六苟道”与“杀伐果断”视角；禁大段道经式说教与章末鸡汤 |
| `urban` | 都市 | `cash_flow`(可用资金/资产)、`public_identity`(明面身份)、`hidden_card`(底牌/马甲/系统)、`network`(人脉/股权/后台)、`cooldown`(金手指规则与限制) | 2~3 章快节奏循环：现实痛点压抑/被轻贱 → 信息差或金手指触发反转 → 利益/尊严精准打脸变现 → 旁观者克制震惊与身份错位 → 新事件切入 | 消费金额、资产数字、时间线必须算术自洽；反派行动需有利益动机；禁“区区几亿随手赏了”式空洞装逼尬词 |
| `general` | 通用男频 | `power_tier`(实力层级)、`core_ability`(核心能力)、`assets`(关键资源/装备)、`relation`(阵营关系)、`status_flag`(当前状态标记) | 标准 5 阶段节拍模板，适配历史架空、末世废土、无限流、硬核科幻 | 通用中文男频防注水规范、禁无意义心理内耗、单段严格适配手机阅读节奏 |

### 3.2 章节情绪极性与章末钩子字典

每章在编排台必须标记一个主情绪极性与章末钩子类型，用于卷级节奏曲线诊断和 Critic 强校验：

| 字段 | 枚举值 | 中文标签 | 编排与审校含义 |
| --- | --- | --- | --- |
| 情绪极性 (`emotion_tag`) | `setup` | 铺垫建场 | 引入新地图、新人物或新利益规则，禁止连续超过 2 章纯 `setup` |
| | `suppress` | 蓄压受阻 | 主角遇强敌、资源受限、被误解或信息劣势，蓄积读者期待 |
| | `turn` | 反转破局 | 掌握关键信息差或亮出部分底牌，局势逆转瞬间 |
| | `burst` | 高潮爆发 | 公开打脸、生死决战、秘境夺魁等情绪与爽感释放峰值 |
| | `harvest` | 落袋留悬 | 战利品清点、实力实质提升，随即抛出下一阶段隐患 |
| 章末钩子 (`hook_type`) | `mystery` | 悬念揭露 | 最后 200 字抛出反常识线索、身份疑点或突发异象 |
| | `crisis` | 突发危机 | 新强敌降临、期限逼近或后院起火，制造即时紧迫感 |
| | `counterattack_eve` | 反击前夜 | 主角刚冷笑布好局或拿到关键道具，只差下一章出手清算 |
| | `reward_pending` | 利益待拆 | 刚打开宝箱/秘境/新权限界面，具体收获留到下章首段揭晓 |
| | `new_arc` | 转场开篇 | 旧矛盾收束，人物踏入新地图或接到核心邀约 |

### 3.3 节拍阶段定义（`beat_stage`）

单章建议编排 3~6 张节拍卡，对应枚举：`setup`（起手建场）、`target`（立靶/抛出利益或冲突）、`suppress`（压制/受挫试探）、`turn`（转折/信息差反转）、`burst`（动作爆发/直接交锋）、`harvest`（收割结算）、`hook`（章末留钩）。

## 4. 领域术语表（Glossary）

全仓代码符号、SQLite 表名与 UI 中文标签严格遵循下表映射，避免同一概念出现多种别名：

| 代码符号 | 数据库表名 | UI 中文名称 | 含义 |
| --- | --- | --- | --- |
| `Book` | `books` | 书籍 | 单部长篇作品根容器，绑定题材包、核心脑洞与导出目录 |
| `Volume` | `volumes` | 卷 | 书籍的一级剧情大弧线单元，包含卷目标与高潮规划 |
| `Chapter` | `chapters` | 章节 | 创作与审改的最小交付单元，承载状态机、正文与钩子配置 |
| `Beat` | `chapter_beats` | 节拍卡 | 章节内部的剧情推进切片（3~6 张/章），绑定 POV 与出场实体 |
| `Hook` | `chapters.hook_*` | 章末钩子 | 章节结尾 200 字必须兑现的留存悬念类型与说明 |
| `Entity` | `entities` | 设定实体 | 角色、势力、地点、道具、力量体系与世界铁律的统一档案 |
| `Invariant` | `entities.is_invariant` | 世界铁律 | 全书硬约束（如“无复活术”），每章生成强制注入且不可被配额裁掉 |
| `StateEvent` | `entity_state_events` | 状态事件 | 按章节号递增的事件溯源记录，构成任意章节时间点的人物/道具快照 |
| `Foreshadowing` | `foreshadowings` | 伏笔 | 记录埋设章、暗示章、计划回收区间与生命周期状态的长期悬念 |
| `ChapterDelta` | `chapter_deltas` | 记忆变更单 | 完章后 AI 自动抽取的增量变更提案，需作者审阅确认才入库 |
| `ContextBriefing` | `chapters.last_briefing_json` | 作战简报 | 上下文编译器实际装配给写作模型的全部材料清单与 Token 分布快照 |
| `StyleProfile` | `style_profiles` | 文风指纹 | 从样章提取的量化句子长度、段落长度、对话占比与叙述语调规范 |
| `LintIssue` | `chapter_audits.lint_json` | AI 味告警 | 0 成本本地规则引擎扫描出的高频套话、结构病与长段落问题定位 |
| `CriticFinding` | `chapter_audits.critic_json` | 审校意见 | 独立 Critic 模型发现的吃书冲突、男频毒点、节拍遗漏与弱钩子 |
| `SurgicalDiff` | `chapter_audits.diffs_json` | 手术润色建议 | 仅针对病灶段落输出的最小局部替换前后对比，支持逐条采纳 |
| `BatchRun` | `batch_runs` | 微批任务 | 一次 1~5 章串行接力生成任务的调度容器与进度追踪记录 |
